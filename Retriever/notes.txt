================================================================================
RETRIEVER — NOTES
================================================================================

Retriever kya hota hai?
  Wo component jo query ke hisaab se relevant documents return karta hai.
  LangChain me aksar vector store se retriever banate ho:
    vectorstore.as_retriever()

Retriever kai types ke ho sakte hain. Mainly 2 tarah classify kar sakte ho:

  1) Data source ke hisaab se
     Matlab retrieve kis data type par query kar rahe ho.
     Example: WikipediaRetriever

  2) Searching algorithm ke basis par
     Example: MMR, MultiQueryRetriever, Contextual Compression


================================================================================
RETRIEVER vs similarity_search
================================================================================

Vector store ki madad se retriever banaya jata hai.

Phir bhi question: hum to vector_store.similarity_search se bhi
search kar sakte the — to retriever hi kyun?

Isliye kyunki retriever me search strategy / algorithm mention kar sakte ho:
  jaise MMR, Multi-query retriever etc.

vector_store.similarity_search method me searching algorithm mention
nahi kar sakte.

similarity_search ka fanda simple hai:
  relevant docs dhoondho aur return kar do.

k ka matlab:
  result me kitne documents return karne hain.


================================================================================
SEARCH STRATEGIES / ALGORITHMS
================================================================================

Is folder / topic me 3 important strategies:

1) Maximal Marginal Relevance (MMR)
2) MultiQueryRetriever
3) Contextual Compression Retriever


================================================================================
1) MAXIMAL MARGINAL RELEVANCE (MMR)
================================================================================

MMR ka goal:
  Query ke liye relevant documents bhi milein,
  aur returned documents ek-doosre ke duplicate / repetitive na hon
  (matlab unka meaning same na ho).

Simple similarity search me problem:
  Agar multiple docs ek hi topic par bahut similar hain (e.g. "LangChain"),
  to top results me almost same meaning wale docs aa jaate hain.

  Example:
    doc1 → LangChain makes it easy to work with LLMs.
    doc2 → LangChain is used to build LLM based applications.
  Dono ka meaning almost same hai.

MMR kaise kaam karta hai?
  Pehle query ke liye relevant docs identify karta hai,
  phir unme se aise docs select karta hai jo:
    - relevant hon
    - aur unka meaning same na ho

Important params:
  k           → final result me kitne documents return karne hain
  lambda_mult → relevance vs diversity ka balance:
                  1.0 → normal similarity search jaisa
                        (repeat ho to koi nahi hataata)
                  0.0 → extreme diverse documents
                        (bilkul alag meaning wale docs pick karega)
                  0.5 → relevance aur diversity ka balanced trade-off

Example:
  Query: "What is langchain?"

  Normal similarity search 3 almost-similar docs return kar sakta hai:
    1. LangChain makes it easy to work with LLMs.
    2. LangChain is used to build LLM based applications.
    3. LangChain supports Chroma, FAISS, Pinecone, and more.

  MMR relevant docs choose karte waqt repetition ko penalize karega.
  Possible ho to different information wala doc select karega
  (jaise Chroma / embeddings / MMR se related info).

MMR ka simple idea:
  "Relevant results lao, lekin same information ko baar-baar mat lao."


================================================================================
2) MULTIQUERY RETRIEVER
================================================================================

Kab use karein?
  Jab user ki query bahut broad / open-ended hoti hai,
  ya query ke multiple meanings / perspectives ho sakte hain.
  Aisi query ko directly vector DB me search karne par
  relevant documents miss ho sakte hain.

Example query: "How to stay healthy?"
  Is query ke multiple aspects ho sakte hain:
    - kaunsi exercise karni chahiye?
    - kya khana chahiye?
    - kitni sleep leni chahiye?
    - exercise aur diet ko kaise maintain karna chahiye?

Kaise kaam karta hai?
  Broad query ko directly search karne ke bajaye
  MultiQueryRetriever original query ko LLM ke paas bhejta hai.
  LLM original query ko samajh kar multiple possible / better
  queries generate karta hai.

Example:
  Original Query: "How to stay healthy?"

  LLM generate kar sakta hai:
    1. "What exercises should I do to stay healthy?"
    2. "What foods should I eat to maintain good health?"
    3. "How should diet and exercise be combined for a healthy lifestyle?"

  Ab ye generated queries ek-ek karke retriever ko di jaati hain.
  Har query ke liye retriever vector DB se relevant docs retrieve karta hai.
  Phir MultiQueryRetriever duplicates hata deta hai
  aur final me unique docs return karta hai.

Overall flow:
  User Query
       ↓
  MultiQueryRetriever
       ↓
  LLM → Multiple Search Queries
       ↓
  Query 1 ──→ Retriever ──→ Relevant Docs
  Query 2 ──→ Retriever ──→ Relevant Docs
  Query 3 ──→ Retriever ──→ Relevant Docs
       ↓
  Duplicate Documents Remove
       ↓
  Unique Relevant Documents

LangChain bhi isi flow ko follow karta hai:
  LLM se queries generate → har query par docs retrieve → unique union return

k=5 ka matlab:
  Har generated query ke liye maximum 5 documents retrieve honge.

  Example:
    3 queries (LLM ne original se generate ki) × 5 docs
    = maximum 15 raw documents

  Duplicates hatne ke baad final 15 se kam bhi ho sakte hain
  (based on kitne duplicates return huye).
  Matlab ek single user query ke result me kitne bhi docs ho sakte hain.


================================================================================
3) CONTEXTUAL COMPRESSION RETRIEVER
================================================================================

Problem:
  Retrieved documents me unnecessary information hoti hai.

Normal retrieval me:
  Retriever relevant document find kar leta hai,
  lekin us document ke andar bahut saari irrelevant info bhi ho sakti hai.

Example:
  Query: "What is photosynthesis?"

  Doc1 content:
    - Grand Canyon ek natural wonder hai.
    - Photosynthesis plants ka sunlight ko energy me convert
      karne ka process hai.
    - Millions of tourists Grand Canyon dekhne aate hain.
    - Rocks millions of years old hain.

  Doc1 overall relevant hai kyunki isme photosynthesis ki info hai,
  lekin agar pura Doc1 de denge to Grand Canyon, tourists, rocks
  wali extra info bhi chali jayegi.

Solution: Contextual Compression Retriever
  Ye is problem ko solve karta hai.
  Normal / base retriever ke upar ek compression layer add karta hai.

  Pehle base retriever relevant docs retrieve karta hai.
  Uske baad compressor (LLM) retrieved docs me user query ke hisaab se
  sirf required info rakhta hai, baaki hata deta hai.
  End me doc milta hai sirf necessary info ke saath.

Compressor (LLM):
  - relevant information rakhta hai
  - irrelevant information remove karta hai

Example:
  Query: "What is photosynthesis?"

  Retrieved Doc1:
    "The Grand Canyon is one of the most visited natural wonders
     in the world. Photosynthesis is the process by which green
     plants convert sunlight into energy. Millions of tourists
     travel to see it every year. The rocks date back millions
     of years."

  Compression ke baad:
    "Photosynthesis is the process by which green plants
     convert sunlight into energy."

  Ab user ko pura document nahi, query ke hisaab se useful info milti hai.

Overall flow:
  User Query
       ↓
  Base / simple Retriever
       ↓
  Fetches Relevant Documents
       ↓
  Contextual Compression By Compressor
       ↓
  Relevant Information Only
       ↓
  User

Main purpose:
  Relevant docs retrieve karne ke baad
  unke andar se query ke liye relevant info extract karna
  aur unnecessary context remove karna.


================================================================================
QUICK DECISION GUIDE
================================================================================

Simple top-k similar docs chahiye          → similarity_search / basic retriever
Relevant + diverse results chahiye         → MMR
Broad / multi-aspect query                 → MultiQueryRetriever
Docs me se sirf useful part chahiye        → Contextual Compression Retriever
