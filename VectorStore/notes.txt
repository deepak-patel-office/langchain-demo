================================================================================
VECTOR STORE — NOTES
================================================================================

Vector Store kya hota hai?
  Wo system jo data ko embeddings (numerical vectors) ki form me store karta hai,
  phir query aane par similar vectors dhoondh ke relevant data return karta hai.

Flow:
  1) documents / text / images → embeddings
  2) embeddings vector store me save
  3) query aayi → query ka bhi embedding banao
  4) similar vectors search karke relevant docs nikaalo


================================================================================
KEY FEATURES
================================================================================

1) Storage
  Vectors + unka metadata store hota hai.
  - in-memory (RAM) → fast, lekin process band hua to data gayab
    (persist alag se karna padta hai)
  - on-disk (SSD/HDD) → durable, bade data ke liye better
  Note: on-disk ko ROM mat samajhna.
        ROM = read-only memory, disk = persistent storage.

2) Similarity Search
  Query vector ke sabse similar vectors retrieve karta hai.
  Common metrics:
    - cosine similarity
    - Euclidean distance
    - inner product (dot product)

3) Indexing
  High-dimensional vectors par fast search ke liye index banata hai.
  Exact nearest neighbor har baar feasible nahi (bahut slow).
  Isliye aksar Approximate Nearest Neighbor (ANN) use hota hai:
    thoda accuracy trade-off, speed bahut zyada.

4) CRUD
  Create → naye vectors add
  Read   → vectors / similar results nikaalna
  Update → existing entry update
  Delete → outdated vectors hataana


================================================================================
USE-CASES
================================================================================

1) Semantic Search   → keyword nahi, meaning ke hisaab se search
2) RAG               → LLM ko relevant context dena
3) Recommender       → similar items / users suggest karna
4) Image/Multimedia  → embeddings se similar media dhoondhna


================================================================================
VECTOR STORE vs VECTOR DATABASE
================================================================================

Dono related hain, same cheez nahi.

Vector Store:
  Lightweight library/service.
  Kaam: embeddings store + similarity search.
  Traditional DB features aksar nahi:
    transactions, rich query language, RBAC, replication etc.
  Prototyping / small apps ke liye achha.
  Example: FAISS
    → search deta hai, lekin persistence, scaling, auth, backup
      alag se handle karna padta hai.

Vector Database:
  Full database jo vectors store + query ke liye bani hai.
  Extra features:
    - horizontal scaling
    - durability / persistence (replication, backup)
    - metadata filters
    - ACID / near-ACID (product pe depend)
    - auth / security
  Production + large datasets ke liye.
  Examples: Pinecone, Qdrant, Weaviate, Chroma
  Note: Chroma ko vector DB bhi kaha jata hai,
        local/dev use bhi common hai.

Simple:
  vector database = vector store + extra DB features
  (scaling, security, filtering, durability)


================================================================================
LANGCHAIN ME VECTOR STORE
================================================================================

LangChain kai stores ke saath integrate karta hai:
  FAISS, Pinecone, Chroma, Qdrant, Weaviate etc.

Scale / features / deployment ke hisaab se backend choose kar sakte ho.

Common interface:
  LangChain ek uniform VectorStore API deta hai.
  Matlab koi si bhi store use karo, pattern almost same rehta hai.
  FAISS se Pinecone switch relatively kam code change se ho sakta hai.
  Exact config thoda alag ho sakta hai, methods same type ke:
    add_documents, similarity_search, as_retriever

Metadata:
  Har document ke saath metadata attach kar sakte ho
  (source, author, timestamp, doc type).
  Isse filter-based retrieval possible hai.
  Example: sirf source="pdf" wale docs search karo.

Short:
  LangChain app aur different vector stores ke beech common layer hai.
  Store, search, filter, backend switch easier.
